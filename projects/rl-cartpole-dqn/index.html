CartPole: from a hand-written rule to a learned policy

CartPole is an inverted pendulum, the textbook control problem, dressed up as an RL benchmark. That makes it the right place to ask what learning gives you that a designed controller doesn't.

1Three agents, one environment

Rather than jumping straight to a DQN, I built up in three steps so each had something to be compared against.

AgentPolicyWhat it establishes
RandomUniform action samplingThe floor: what zero information looks like
Rule-basedHand-written on pole angleWhat domain knowledge alone achieves
DQNLearned Q-functionWhat learning adds on top

The rule-based controller matters most. It's easy to be impressed by an RL agent balancing a pole until you write twenty lines that push the cart in the direction the pole is falling and watch that do respectably too. Having that baseline in front of me kept the comparison honest.

2Training

The moving average climbs, which is the result you want. The raw per-episode reward underneath it is more interesting: it stays noisy well after the average looks healthy. A DQN that has "solved" CartPole on average can still drop an episode, because ε-greedy exploration keeps injecting random actions and the Q-function is being chased by its own bootstrapped targets.

The gap between the average and the worst case is the whole problem with putting RL on hardware. A control engineer asks for a stability guarantee; a reward curve offers a trend.

3What I took from it

  • Exploration against exploitation is a scheduling problem. The ε decay schedule changed results more than the network architecture did.
  • Replay buffers exist to break correlation. Consecutive frames of a falling pole are almost the same sample.
  • A value function is not a controller. It's an estimate of return that a policy is derived from, and the derivation is where the fragility lives.

4Where this went

CartPole was a stepping stone. The continuation is continuous-control manipulation with PPO and TQC, and constrained RL in MuJoCo. LunarLander with a DQN is still planned.
