SLAM and navigation on a mecanum base

A full localisation and navigation stack for a simulated omnidirectional robot in a warehouse. The headline measurement is how badly wheel odometry alone drifts, and how much each layer of the stack buys back.

Year2026

CodeGitHub ↗

1Pipeline

The starting point was a supplied robot package with bugs in it, which I fixed first. On top of it I built:

  • Mapping: slam_toolbox.
  • State estimation: an EKF from robot_localization.
  • Localisation on a known map: AMCL with the omnidirectional motion model.
  • Planning and control: Nav2 with the Smac 2D planner and the MPPI controller.
  • Command arbitration: twist_mux.

MPPIModel Predictive Path Integral control (Williams et al., 2017), a sampling-based MPC. It suits a holonomic base because it can sample lateral velocity directly. is a good match for a mecanum base, where sideways motion is a free action dimension.

2Measured drift

Position error on 50–80 m paths in the simulated warehouse.
Source of poseError
Raw wheel odometry35–55 m (about 70% of distance)
EKF fed ground-truth-derived odometry0.00–0.01 m
SLAM-corrected pose0.02–0.04 m

The EKF row is not a realistic estimate. Its input was derived from simulator ground truth, so it shows what the filter does with a perfect measurement. The SLAM-corrected row is the honest one.

3What I would do next

  • Replace the ground-truth-derived input with realistic wheel odometry plus IMU, and report the EKF error again.
  • Drive a coverage path so the map is complete before evaluating AMCL against it.
  • Compare MPPI against the other Nav2 controllers on the same paths.
